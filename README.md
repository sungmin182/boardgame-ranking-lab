# 보드게임 랭킹 랩

BGG(BoardGameGeek) 데이터를 **내가 정한 기준으로 다시 정렬**하는 보드게임 랭킹 사이트.
빌드 도구 없이 정적 파일로 돌아간다.

**사이트 → https://sungmin182.github.io/boardgame-ranking-lab/**

```
npm run sync    # 데이터 수집 → data/games.json 생성 (첫 실행 약 8분)
npm run dev     # http://localhost:4173
```

---

## 1. 데이터가 어디서 오는가

BGG 공식 XML API(`/xmlapi2`)는 **2025년부터 Authorization 토큰이 필수**가 되어
토큰 없이 호출하면 `401 Unauthorized`를 돌려준다. 그래서 두 경로를 조합한다.

| 무엇 | 출처 | 갱신 |
| --- | --- | --- |
| 전체 순위·평점·평가 수 | [beefsack/bgg-ranking-historicals](https://github.com/beefsack/bgg-ranking-historicals) — BGG 일별 랭킹 덤프를 매일 커밋하는 저장소 | 매일 (UTC 01:00경) |
| 난이도·추천 인원·시간·메커니즘 | `api.geekdo.com/api/geekitems`, `api/dynamicinfo` — BGG 웹사이트 자신이 쓰는 공개 JSON | 요청 시점 |

랭킹 저장소에는 **2016년치부터 하루 단위 스냅샷이 전부 남아 있다.** 덕분에
"최근 30일 순위 상승률" 같은 지표를 직접 몇 달 모으지 않고 첫날부터 쓸 수 있다.
`scripts/sync-ranks.mjs`가 오늘/7일 전/30일 전/1년 전 스냅샷을 받아 변화량을 계산한다.

> 공식 토큰을 발급받고 싶다면 BGG의 [Using the XML API](https://boardgamegeek.com/using_the_xml_api)
> 에서 프로젝트를 등록하면 된다. 승인 후 `Authorization: Bearer <토큰>` 헤더로 `/xmlapi2`를 쓸 수 있다.
> 지금 구조로도 필요한 값은 전부 나오므로 필수는 아니다.

### "실시간"에 대해

BGG의 순위와 베이즈 평점은 **하루 한 번** 재계산된다. 초 단위 실시간이라는 것은 원래 없다.
이 사이트는 그래서 두 층으로 나눠 놓았다.

1. **매일 자동 동기화** — GitHub Actions가 매일 새 데이터를 받아 사이트를 다시 배포한다 (`.github/workflows/sync.yml`).
2. **개별 게임 라이브 조회** — 상세 패널의 `실시간 새로고침` 버튼이 그 순간의 값을 직접 물어본다.

2번은 선택 사항이다. `api.geekdo.com`이 CORS 헤더를 주지 않아 브라우저에서 직접 부를 수 없기 때문에
아주 얇은 중계 서버가 하나 필요하다. `proxy/worker.js`를 Cloudflare Workers에 붙여넣고(무료, 1~2분)
발급된 주소를 `assets/config.js`의 `LIVE_PROXY`에 적으면 버튼이 나타난다.
비워두면 매일 갱신되는 데이터만으로 정상 동작한다.

## 2. 나만의 랭킹 점수

이 사이트의 핵심. 정렬 기준을 고르는 게 아니라 **점수식을 직접 만든다.**

7개 축에 −100 ~ +100 가중치를 주면

```
점수 = Σ (가중치 / 100) × 백분위(축)
```

로 계산해 실시간 재정렬한다. 각 축은 원시값이 아니라 **전체 1500개 중 백분위**로 환산해서 쓴다.
평점 8.4와 평가 수 6만은 단위가 달라 그대로 더할 수 없고, 백분위는 카탄처럼 평가 수가
압도적인 이상치에 결과가 끌려가지 않기 때문이다.

| 축 | 의미 | 음수로 두면 |
| --- | --- | --- |
| 긱 평점 | BGG 베이즈 평점 | 저평점 우선 |
| 유저 열기 | 유저 평균 − 베이즈 평점. 평가 수가 적어 순위에 덜 반영된 정도 | 과대평가된 게임 |
| 인기도 | 평가 수(로그) | **숨은 게임 발굴** |
| 상승세 | 최근 30일 순위 상승률 | 하락 중인 게임 |
| 최신성 | 출시 연도 | 고전 명작 |
| 가벼움 | 난이도가 낮을수록 높음 | 헤비겜 우선 |
| 보유율 | 실제 소장자 수 | 안 사고 평가만 한 게임 |

프리셋 7종(`긱 기본`, `숨은 명작`, `요즘 뜨는`, `신작 헌터`, `가족·입문`, `헤비 전략`, `검증된 스테디`)이
출발점으로 들어 있다. 새 프리셋을 추가하려면 `assets/app.js`의 `PRESETS`에 한 줄 넣으면 된다.

**모든 상태는 URL에 담긴다.** 가중치·필터·정렬을 맞춘 뒤 `링크 복사`를 누르면
그 화면 그대로 열리는 주소가 나온다.

## 3. 기능

- **필터** — 인원(베스트/추천 구분), 난이도, 플레이 시간, 출시 연도, BGG 순위, 평가 수,
  메커니즘·카테고리(클릭할 때마다 포함 → 제외 → 해제 3단계), 상승 중인 게임만,
  언어 무관 게임만, 국내 정발판만, 내 목록만,
  사놓고 한 번도 안 한 것만, 내가 평점을 매긴 것만.
  순위는 `TOP 100` `~500` `500–2000` 처럼 구간 칩으로 바로 집을 수 있다 —
  1만 줄을 스크롤로 훑지 않기 위한 장치다.
- **화면 배치** — 넓은 화면(1180px 이상)에서는 점수·필터가 왼쪽 사이드바로 가고
  결과 표가 오른쪽에 항상 떠 있다. 사이드바는 따로 스크롤되므로 가중치를 만지는
  동안 표가 눈에서 사라지지 않는다. `☰`로 접으면 표가 화면 전체 폭을 쓴다.
  좁은 화면에서는 예전처럼 위아래로 쌓인다.
- **패널 접기** — 점수·필터 패널은 제목의 `▾`로 접는다(상태는 기억된다).
  슬라이더 7개짜리 점수 패널이 928px → 140px가 되어 사이드바 스크롤이 사라진다.
  접어도 **프리셋 버튼은 그대로 남고**, 제목 옆에 `· 숨은 명작`이나
  `· 직접 조절 (긱 평점 +40, …)` 같은 한 줄 요약이 붙는다 —
  지금 설정을 확인하려고 다시 펴야 한다면 접는 의미가 없기 때문이다.
- **표 / 카드** — 값을 비교할 때는 표, 훑어볼 때는 표지 위주의 카드. 오른쪽 위에서
  전환하고 선택은 기억된다. 둘 다 스크롤하면 80개씩 이어서 불러오며,
  하단에 "N개 중 M개 표시"가 뜬다.
- **표** — 13개 컬럼 정렬, 간결 모드, CSV 내보내기
- **상세 패널** — 스펙 전체, 7·30·365일 변동, 분야별 순위,
  BGG·보드라이프·부마갤 바로가기.
  왼쪽 모서리를 끌어 폭을 조절할 수 있다(기억되며, 더블클릭하면 기본값).
  손잡이와 닫기 버튼은 패널의 보이는 영역에 고정돼 있어 **어디까지 내려가도 잡힌다**
  — `absolute` 로 두면 스크롤 내용에 붙어 함께 밀려 올라가서 맨 위에서만 잡혔다.
  맨 아래에도 `닫기` 버튼이 있고, `Esc` 로도 닫힌다(상세 → 서재 → 비교 순).
- **순위 추이 그래프** — 최근 5년, 분기마다 한 점씩 21개. 점에 마우스를 올리면
  그 시점의 연월과 순위가 뜬다. 세로축은 로그 척도다 — 1위와 5위의 차이가
  3000위와 3004위의 차이보다 크고, 신작이 16000위에서 시작하면 선형 축에서는
  상위권이 한 줄로 뭉개지기 때문이다.
- **비교 뷰** — 행의 `⇄` 버튼으로 최대 4개까지 담아 스펙 16종을 나란히 비교한다.
  항목별로 더 나은 값을 강조하고(전부 같으면 강조하지 않는다), 순위 추이를 한 그래프에
  겹쳐 그리며, 공통 메커니즘과 각 게임에만 있는 메커니즘을 나눠 보여준다.
- **BGG 리뷰** — 게임을 열면 그때 조회해 내용이 있는 리뷰 10개를 보여준다.
  앞부분만 싣고 전체는 원문 링크로 넘긴다. `LIVE_PROXY`가 설정돼 있어야 나타난다.
  기본적으로 **한국어로 번역해서** 보여주며, `원문 보기`로 전환할 수 있다(설정은 기억된다).
  번역은 Cloudflare Workers AI가 워커 안에서 처리한다 — 외부 번역 서비스에 키를 맡기지 않는다.
  같은 글은 30일간 캐시되므로 두 번째부터는 모델을 다시 부르지 않는다.
- **국내 정발 표시** — 한글 발매명이 있거나 국내 발매사가 등록된 게임에 `정발`
  배지가 붙고, 필터로 그것만 추릴 수 있다. 판정 근거는 전부 BGG가 갖고 있는
  자료다(국내 사이트를 긁지 않는다). 발매사 목록은 `data/kr-publishers.json`.
- **내 기록** — 게임마다 내 평점(0~10), 구입가·구입일·구입처, 판매가·판매일·판매처,
  적정가, 목표가, 자유 메모, 그리고 플레이 기록(날짜·인원·승자·소요 시간·메모)을 적는다.
  적기만 하면 나머지는 계산된다.

  - **내 평점은 별 다섯 개**로 매긴다. 별 반 개가 1점이라 0.5칸씩 최대 10점.
    마우스를 올리면 그 지점까지 미리 채워 보여주고, 같은 점수를 다시 누르면 지워진다.
    숫자로 바로 넣고 싶으면 옆 칸에 적으면 된다.
  - **플레이는 "총 몇 판" 숫자만 적어도 된다.** 예전에 산 게임을 수십 판씩 했는데
    한 판씩 입력하게 하면 아무도 안 적는다. 숫자만 넣어도 1판당 비용과
    "아직 안 한 것"이 동작하고, 날짜·승자까지 남기고 싶을 때만 아래 자세한 기록을 쓴다.
    (내부적으로는 `자세한 기록 수 + 세어만 둔 판수`로 합산한다.)
  - **구입처·판매처는 목록에서 고른다.** `+ 직접 입력…`으로 새 항목을 적으면
    다음부터 그 목록에 그대로 남는다(`lz.places`에 저장).

  | 나오는 값 | 계산 |
  | --- | --- |
  | 1판당 비용 | 구입가 ÷ 플레이 수 |
  | 손익 | 판매가 − 구입가 |
  | 마지막 플레이 | 플레이 기록 중 최신 날짜 |

  **내 평점은 점수 슬라이더의 축으로도 들어간다.** 그래서 `내 평점 +100 · 상승세 +40`
  같은 나만의 정렬이 된다. 프리셋 `내 취향순`이 그 예다.
  표에는 `내 평점 · 플레이 · 1판당` 열이 붙는다(기록이 하나라도 생기면 자동으로 켜진다).
- **내 서재** — 결과 패널의 `내 서재` 버튼. **표의 표시 버튼과 그대로 이어진다.**
  ● 를 누른 게임이 `보유 중`, ○ 가 `방출함`, ★ 가 `관심` 목록에 쌓인다.
  값을 하나도 안 적고 버튼만 눌러도 목록에 들어온다.
  여기에 쓴 돈·되판 돈·순지출, 총 플레이, 1판당 평균 비용,
  **H-지수**(N개를 각각 N판 이상 — 한 게임만 100판 한 사람과 100개를 골고루 한
  사람을 구분한다), BGG 평점과 내 평점의 평균 차이가 함께 나온다.
  **사놓고 아직 안 한 게임**(보유 중인데 플레이 0판)과 **180일 넘게 안 꺼낸 게임**도
  목록으로 뜬다. 보유 목록은 구입가, 방출 목록은 손익, 관심 목록은 목표가를 달고
  있고, 목록마다 색이 다르다(보유 초록 · 방출 빨강 · 관심 금색).

  **서재에서 게임을 누르면 서재 위에 상세 패널이 겹쳐 열린다.** 서재를 닫고
  랭킹 화면으로 돌아가지 않는다 — 그러면 게임 하나를 확인하고 목록으로 돌아오는
  흐름이 매번 끊기기 때문이다. 상세 패널의 z-index가 서재보다 높은 이유가 이것이다.
  패널에서 표시나 기록을 바꾸면 뒤의 서재도 곧바로 다시 계산된다.

  각 구역은 **서재 안에서 바로 표지 카드로** 볼 수 있다(`목록으로`/`카드로` 전환,
  선택은 기억된다). 한 구역에 60장까지 그리고, 그보다 많으면
  `결과 화면에서 보기 →`로 넘어가 정렬·검색까지 쓸 수 있다.
- **기록 백업** — 기록은 이 브라우저에만 있다. `내 서재`에서 JSON으로 내보내고
  가져올 수 있다. 가져오기는 **덮어쓰지 않고 게임 단위로 합치며**, 겹치는 게임이
  있으면 먼저 물어본다. 다른 기기에서 적은 것을 합칠 때 한쪽이 사라지면 안 되기 때문이다.
- **내 목록** — 관심(★)·보유(●)·**방출(○)**·제외(✕)를 브라우저에 저장.
  네 개가 나란히 붙어 있어 **각각 다른 색**을 준다. 회색 두 개나 초록 두 개가
  섞이면 무엇이 켜져 있는지 한눈에 안 들어오기 때문이다.

  | 표시 | 색 | 뜻 |
  | --- | --- | --- |
  | ★ 관심 | 금색 | 갖고 싶은 것 |
  | ● 보유 | 초록 | 지금 있는 것 |
  | ○ 방출 | 빨강 | 있었지만 내보낸 것 |
  | ✕ 제외 | 회색 | 목록에서 숨기기만 함 (수집과 무관하므로 가장 약하게) |

  채워진 버튼의 글자색은 `--on-fill` 토큰을 따른다. 다크 모드에서는 강조색이
  밝아져서 흰 글자를 얹으면 대비가 2.2:1까지 떨어지기 때문에 어두운 글자로 바꾼다
  (지금은 라이트 5.1:1, 다크 6.7:1 이상).
  제외할 때는 확인창이 뜨고, 직후 토스트에서 되돌릴 수 있다.
  필터 패널에 "제외한 게임 N개 · 보기 · 모두 해제"가 표시된다.

  **기록과 표시는 서로 맞춰진다.** 구입가를 적으면 아직 아무 표시가 없던 게임이
  보유(●)로, 판매가를 적으면 방출(○)로 바뀐다. 손으로 두 번 누르지 않아도 된다.

  표시는 표의 작은 아이콘 말고 **상세 패널 위쪽의 큰 버튼**으로도 바꿀 수 있다.
  기록을 적다가 표시까지 고치려고 패널을 닫을 일이 없다.
- **내 목록만 골라 보기** — 필터의 `내 목록` 칩(`★ 관심` `● 보유` `○ 방출`
  `아직 안 한 것` `평점 매김`)을 누르면 결과 화면이 그 목록만 담는다.
  **평소처럼 표/카드로 훑고 정렬하고 검색할 수 있다** — 서재의 이름 목록은
  세기에는 좋지만 표지가 없어 고르기에는 불편하기 때문이다.
  서재의 각 구역에 있는 `카드로 보기 →` 버튼이 같은 곳으로 데려간다.
  상태는 URL에 `?list=own` 처럼 남는다.
- 다크 모드, 한글명 표시, `/` 키로 검색창 포커스

## 4. 구조

```
index.html            화면
assets/app.js         전체 로직 (필터·점수·정렬·렌더·URL 상태)
assets/style.css      테마 토큰과 스타일
assets/config.js      LIVE_PROXY 주소 설정
scripts/sync-ranks.mjs    ① 일별 랭킹 스냅샷 + 변화량 계산
scripts/sync-details.mjs  ② 게임별 상세 정보 수집 (cache/details 에 캐시)
scripts/build.mjs         ③ 둘을 합쳐 data/games.json 생성
scripts/serve.mjs         로컬 미리보기 서버
proxy/worker.js       실시간 조회용 Cloudflare Worker (선택)
data/korean-names.json   BGG id → 한글명 매핑 (직접 추가하는 파일)
data/kr-publishers.json  국내 발매사 목록 (직접 추가하는 파일)
```

현재 상위 **10000위**까지 수집한다. 개수는 환경변수로 조절한다.

```bash
LIMIT=3000 npm run sync    # 상위 3000위까지
```

바꿨다면 `.github/workflows/sync.yml`의 `LIMIT`도 같은 값으로 맞춰야
매일 동기화가 같은 범위를 유지한다.

**왜 1만인가.** 랭킹 덤프에는 순위가 붙은 게임이 31,137개 들어 있지만 전부
쓸모 있는 것은 아니다. 순위가 내려갈수록 표본이 얇아진다.

| 순위 | 평가 수 |
| --- | --- |
| 1,000위 | 4,270 |
| 3,000위 | 1,384 |
| 5,000위 | 425 |
| 10,000위 | 407 |
| 15,000위 | **53** |

1만위까지는 400개대를 유지하다가 그 아래에서 두 자리로 떨어진다. 평가 50개짜리
게임은 평점도 순위도 흔들려서 "내 기준으로 다시 정렬"의 재료가 되지 못한다.
그래서 1만에서 끊는다.

### 한 번에 다 받아지지 않는다

**BGG는 요청량이 일정 수준을 넘으면 429(요청 과다)로 막고 한동안 풀어주지 않는다.**
1만 개를 한 번에 받으려다 두 번 막혔다(5000개 부근, 재개 후 475개 부근).
한도는 공개돼 있지 않다. 그래서 수집은 **여러 회차에 나눠 채우는** 구조다.

| 설정 | 기본값 | 뜻 |
| --- | --- | --- |
| `MAX_NEW` | 1200 | 실행 한 번에 새로 받을 최대 개수 |
| `TTL_HOURS` | 336 (14일) | 이 시간이 안 지난 캐시는 그대로 씀 |
| `CONCURRENCY` | 2 | 동시 요청 수 |
| `PACE_MS` | 350 | 요청 사이 간격 |

아직 안 받은 게임은 다음 회차에서 자연히 1순위가 되므로, 매일 도는 CI가
며칠에 걸쳐 1만 개를 채운다. **그동안에도 사이트는 이미 받은 만큼으로 정상
동작한다** — `build.mjs`가 상세 정보 없는 게임을 건너뛰기 때문이다.

TTL을 14일로 둔 이유도 여기 있다. 7일이면 하루 갱신분(약 1430개)만으로 상한을
다 써버려서 미수집분이 영영 채워지지 않는다. 14일이면 갱신분이 약 714개라
나머지 여유로 밀린 것을 채운다. 매일 바뀌는 값(순위·평점·평가 수)은 어차피
랭킹 덤프에서 오고, 여기서 받는 값(난이도·인원·메커니즘)은 거의 변하지 않는다.

상한에 걸린 뒤에도 **캐시가 있으면 형식이 옛것이어도 버리지 않는다.** 버리면
배포본의 게임 수가 오히려 줄기 때문이다.

`data/games.json` 크기는 게임 수에 거의 비례한다. 1만 개면 원본 약 13.8MB,
전송은 gzip이 걸려 약 3.5MB다(GitHub Pages가 JSON을 자동으로 압축해 보낸다).

### 용어 한글화

카테고리·메커니즘은 `assets/terms.js`에서 한글 이름과 한 줄 설명으로 바꿔 보여준다
(카테고리 85개 + 메커니즘 192개 = 277항목, 데이터에 등장하는 용어를 전부 덮는다).

```js
'Worker Placement': ['일꾼 놓기', '말을 자리에 두어 그 행동을 차지'],
```

설명은 이름만으로 짐작되는 것(판타지, 좀비 …)은 비워 둔다. 마우스를 올리면
원어와 설명이 함께 뜬다. **필터와 URL은 계속 영문 원어를 키로 쓰므로**,
이 파일을 고쳐도 예전에 공유한 링크는 그대로 동작한다.
사전에 없는 용어는 원어가 그대로 표시되므로 BGG에 새 용어가 생겨도 화면이 비지 않는다.

### 한글명

**BGG가 각국 발매명을 갖고 있어서, 한글명은 자동으로 붙는다.** `geekitems` 응답의
`alternatenames`에서 한글이 든 이름을 골라내 쓴다. 국내 정발판이 있으면 실제 상품명이
그대로 들어온다 — Spirit Island는 "스피릿 아일랜드"가 아니라 **정령섬**, Twilight Imperium
4판은 **여명의 제국**이다.

커버리지는 순위가 내려갈수록 떨어진다. 국내에 안 들어온 게임이 그만큼 많다는 뜻이다.

| 구간 | 한글명 | 국내 정발 |
| --- | --- | --- |
| 100위까지 | 100% | 100% |
| 300위까지 | 99% | 99% |
| 700위까지 | 89% | 89% |
| 1500위까지 | 60% | 62% |
| 3000위까지 | 41% | 44% |
| 5000위까지 | 29% | 32% |

정발 비율이 한글명보다 조금 높은 것은 `kr-publishers.json`으로 더 잡아낸 몫이다.

한 게임에 이름이 여러 개 달리는 경우(변형판·개정판)에는 **가장 짧은 것을 대표로** 쓰고
나머지는 검색용 별칭으로 남긴다. "사이쓰"로 검색해도 **사이드**(Scythe)가 나오고,
"아줄 미니"로 검색해도 **아줄**이 나온다.

BGG에 한글명이 없거나 마음에 들지 않으면 `data/korean-names.json`으로 덮어쓴다.
이 파일이 항상 우선한다.

```json
{
  "337627": "보이드폴",
  "371942": "화이트 캐슬"
}
```

넣은 뒤 `npm run build`를 다시 돌리면 반영된다.

## 5. 배포 (현재 구성)

| 무엇 | 어디 | 주소 |
| --- | --- | --- |
| 사이트 | GitHub Pages (Actions 배포) | https://sungmin182.github.io/boardgame-ranking-lab/ |
| 실시간 조회 프록시 | Cloudflare Workers | https://bgg-live-proxy.boardgame-ranking-lab.workers.dev |

`.github/workflows/sync.yml`이 매일 한국시간 오전 11시에 데이터를 갱신하고 다시 배포한다.
Actions 탭의 `Run workflow`로 즉시 실행할 수도 있다.

워커를 고쳤을 때는 다시 올려야 한다(사이트 배포와 별개다).

```bash
npx wrangler deploy --config proxy/wrangler.toml
```

사이트 주소가 바뀌면 `proxy/worker.js`의 `ALLOWED_ORIGINS`에 새 주소를 넣고 재배포할 것.
목록에 없는 출처에서 부르면 브라우저가 응답을 버린다.

### 처음부터 다시 세팅할 때

1. GitHub 저장소를 만들고 푸시한다(Pages 무료 배포는 **공개 저장소**만 된다).
2. Settings → Pages → Source를 **GitHub Actions**로 바꾼다.
3. Cloudflare에서 workers.dev 서브도메인을 한 번 등록한 뒤 위 배포 명령을 실행한다.
4. 발급된 주소를 `assets/config.js`의 `LIVE_PROXY`에 적는다.

## 6. 예의에 관한 메모

- 수집 스크립트는 **동시 2개, 요청 사이 350ms, 7일 캐시**로 동작한다.
  `CONCURRENCY`나 `PACE_MS`를 공격적으로 바꾸지 않는 편이 좋다.
  실제로 동시 4 + 120ms 로 1만 개를 받다가 5천 개 지점에서 **429(요청 과다)** 를
  맞아 그 뒤 요청이 전부 막힌 적이 있다. 한 번 막히면 몇 분간 풀리지 않는다.
- 429를 받으면 `Retry-After`를 그대로 따르고, 없으면 4초부터 지수적으로 늘려 쉰다.
- 요청에는 45초 타임아웃이 걸려 있다. Node의 `fetch`는 기본 타임아웃이 없어서
  연결 하나가 물리면 워커가 영영 기다리는데, 동시 실행이 전부 물리면 수집이
  아무 로그도 없이 멈춘다(실제로 겪었다).
- `api.geekdo.com`은 BGG가 문서로 공개한 API가 아니라 자사 웹사이트가 쓰는 엔드포인트다.
  예고 없이 바뀔 수 있으므로, 장기적으로는 XML API 토큰을 발급받아 옮겨가는 쪽이 안전하다.
- **보드라이프와 부루마블 갤러리(디시인사이드)는 크롤링하지 않는다.**
  두 곳 모두 `robots.txt`가 `ClaudeBot` / `Claude-Web` / `anthropic-ai` 를
  이름으로 지목해 `Disallow: /` 하고 있다. 보드라이프는 여기에 더해
  `curl`·`wget`·`python-requests`·`Node/fetch`·`Scrapy` 도 막고,
  `Content-Signal`이 `ai-train=no, use=reference` 다.
  그래서 **데이터를 가져오지 않고 검색 링크만 연결한다** — `use=reference`가
  허용하는 방식이고, 국내 시세·후기는 그쪽에서 직접 읽는 구조다.
  UA를 바꾸거나 프록시를 끼워 우회하지 말 것. 명시적 거부를 무시하는 것이 된다.
  다른 국내 사이트를 붙일 때도 robots.txt를 먼저 볼 것.
